# پادشاهی ۲۰۴۸ · Kingdom 2048

بازی ادغام سه‌بعدی با Vite، Three.js و رابط فارسی راست‌به‌چپ.

```sh
npm install
npm run dev
```

آدرس نمایش‌داده‌شده توسط Vite را باز کنید. برای ساخت نسخهٔ انتشار از `npm run build` و برای مشاهدهٔ آن از `npm run preview` استفاده کنید.

## بازی و ساختار

- کلیدهای جهت، کلیدهای فیزیکی WASD حتی با صفحه‌کلید فارسی، یا کشیدن ماوس و انگشت در امتداد قطرهای صفحه، سازه‌ها را حرکت می‌دهند. جهت درگ از تصویر محورهای واقعی صفحه در دوربین محاسبه می‌شود و آستانهٔ حرکت ۲۴ پیکسل است. ضربه و کلیک بدون درگ همچنان در حالت جابه‌جایی سازه‌ها را انتخاب می‌کنند. نشان هر سازه مقدار ۲۰۴۸ آن را با رقم فارسی نمایش می‌دهد.
- انتخاب‌گر کنار نام سرزمین و پنجرهٔ «استایل‌ها»، تم‌های بازشده را بدون شروع دوباره عوض می‌کنند. «سرزمین‌ها» دانشنامهٔ ۱۳ سطح سازه را نشان می‌دهد و «برترین‌ها» جدول روزانه و کل را باز می‌کند.
- هر کمک فقط یک بار در ذخیرهٔ همان کاربر قابل مصرف است. شروع مجدد، جمعیت کل، رکورد سازه، سرزمین فعال و کمک‌های مصرف‌شده را حفظ می‌کند. بازگشت فقط صفحه، جمعیت فعلی و تعداد حرکت‌های قبل از آخرین حرکت را برمی‌گرداند.
- آستانه‌های تازهٔ سرزمین‌ها به‌ترتیب ۰، ۳۰۰٬۰۰۰، ۱٬۰۰۰٬۰۰۰، ۲٬۵۰۰٬۰۰۰ و ۵٬۰۰۰٬۰۰۰ نفر است. ذخیره‌های قدیمی سرزمین‌های قبلاً کسب‌شده را حفظ می‌کنند؛ نسخهٔ توازن و فهرست سرزمین‌های بازشده در همان ذخیره نگه داشته می‌شود و نیازی به پاک کردن پیشرفت نیست.
- جارو همهٔ سازه‌های سطح ۱ و ۲ را حذف می‌کند. اگر هیچ سازه‌ای باقی نماند، یک سازهٔ تازه برای ادامهٔ همان دور ظاهر می‌شود.
- فایل‌های اصلی تأمین‌شده بدون تغییر در `theme/` قرار دارند؛ نام پوشهٔ اولیهٔ محیط `themes/` بود و برای هماهنگی با مسیر درخواستی، فقط نام پوشه تغییر کرده است.
- `src/game/boardLogic.js` قوانین مستقل صفحه، `GameEngine.js` رندر و کنترل‌ها، و `src/state/GameState.js` وضعیت و ذخیره‌سازی را نگه می‌دارند.

## صدا و ذخیره‌سازی

همهٔ آدرس‌های `src/audioConfig.js` خالی‌اند؛ توضیح فارسی بالای هر آدرس، سبک و زمان دقیق پخش را مشخص می‌کند. تا زمان افزودن فایل، Web Audio موسیقی امبینت زنده با نت‌های پراکندهٔ پنتاتونیک، پدهای آرام و فاصله‌های تصادفی تولید می‌کند. فیلتر پایین‌گذر ۷۵۰ هرتز، ورود ۰٫۴ ثانیه‌ای و محو شدن ۲٫۲ ثانیه‌ای نت‌ها، صدا را گرم و ملایم نگه می‌دارد. پخش و زمان‌بندی هنگام پنهان شدن صفحه متوقف می‌شود. فایل‌های جایگزین را می‌توان در `public/audio/` قرار داد و آدرس‌هایی مثل `/audio/move.mp3` وارد کرد؛ موسیقی فایلی همچنان لوپ می‌شود. دکمهٔ صدا، موسیقی و افکت‌ها را با هم قطع می‌کند و انتخاب را ذخیره می‌کند.

وضعیت با نسخهٔ طرح `۱` زیر کلید `kingdom2048:state:v1` در `localStorage` ذخیره می‌شود. `GameState` یک آداپتر ذخیره‌سازی قابل تعویض می‌پذیرد. `exportSnapshot()` برای ذخیرهٔ محلی و `getSyncPayload()` برای همگام‌سازی آینده است؛ توکن در دادهٔ ارسالی همگام‌سازی قرار نمی‌گیرد. فعلاً هویت کاربر همان ذخیرهٔ محلی مرورگر است؛ اجرای محدودیت کمک‌ها در چند دستگاه و احراز هویت به بک‌اند مرحلهٔ سوم نیاز دارد.

برای رابط مرحلهٔ دوم، `window.kingdom2048` متدهای `switchTheme(id)`، `newRun()`، `getSnapshot()` و `getSyncPayload()` را فراهم می‌کند. درخواست تعویض تم حین حرکت صف‌بندی می‌شود. وضعیت فقط از مسیر `GameState` تغییر می‌کند.

## رابط و سرویس مرحلهٔ دوم

در نخستین ورود، پنجرهٔ خوشامد تا انتخاب نام کاربری معتبر بسته نمی‌شود. نام باید ۳ تا ۱۶ نویسه و شامل حروف فارسی یا انگلیسی، عدد یا زیرخط باشد. ثبت نام، جمعیت و کمک‌های مصرف‌شدهٔ ذخیرهٔ قبلی را حفظ می‌کند. هنگام باز بودن هر پنجره، ورودی بازی متوقف می‌شود؛ پیمایش پنجره و صفحه‌کلید همچنان کار می‌کنند. کلید Escape و کلیک روی پس‌زمینه، پنجره‌های معمول را می‌بندند.

`src/services/ApiService.js` چهار متد ناهمگام `registerUsername`، `consumePowerup`، `submitScore` و `getLeaderboard` را فراهم می‌کند. پاسخ‌ها دادهٔ ساده و مستقل از رابط‌اند و خطاها متن فارسی دارند. آداپتر محلی با تأخیر کوتاه، ۱۰ بازیکن نمونه و رکورد بازیکن فعلی، زیر کلید `kingdom2048:api:v1` ذخیره می‌شود. یکتایی نام‌ها و رکوردها فعلاً به همان مرورگر محدود است؛ اتصال سراسری ArvanCloud در مرحلهٔ سوم اضافه می‌شود. سازندهٔ سرویس، `transport({ method, payload, token })` را برای جایگزینی آداپتر محلی می‌پذیرد. توکن محلی صرفاً شناسهٔ نشست نمونه است.

رتبه‌بندی بر اساس بیشترین جمعیت یک دور است. روز رقابت با منطقهٔ زمانی تهران محاسبه می‌شود. `runId` ذخیره‌شده و شناسهٔ ارسال، ثبت دوبارهٔ نتیجه پس از تازه‌سازی صفحه را بی‌اثر می‌کنند. در بازی ادامه‌یافته با کمک‌ها، نتیجهٔ بالاتر همان دور می‌تواند رکورد را ارتقا دهد. صفِ تأیید کمک‌ها، حرکت هم‌زمان و مصرف دوباره را متوقف می‌کند؛ ورود به حالت جابه‌جایی یا انصراف از آن هیچ کمکی مصرف نمی‌کند. خطای سرویس نیز صفحه و تعداد کمک‌ها را حفظ می‌کند.

`src/game/ThumbnailRenderer.js` یک رندرر مشترک و جدا از رندرر بازی را هنگام راه‌اندازی می‌سازد. تصاویر شفاف ۱۸۰×۱۸۰ کاخ نهایی پنج تم و همهٔ سطوح تم فعال در زمان‌های بیکار آماده و با کلید تم/سطح نگه‌داری می‌شوند. با تعویض سرزمین، پیش‌نمایش‌های سرزمین جدید در اولویت قرار می‌گیرند. باز و بسته کردن پنجره‌ها کانتکست WebGL تازه‌ای نمی‌سازد. `GameUI` محتوای پنجره‌ها و `ModalManager` تمرکز، بستن، پس‌زمینه و گذارهای آن‌ها را مدیریت می‌کنند. متدهای عمومی `openKingdoms()`، `openThemes()` و `openLeaderboard(period)` نیز روی `window.kingdom2048` در دسترس‌اند.

نخستین ادغام به سطح ۱۳ در هر دور جشن دارد؛ بازگشت یا بارگذاری مجدد، جشن را تکرار نمی‌کند. پایان بازی نتیجه را ثبت می‌کند و نشان رکورد، پیشرفت سرزمین بعدی و شروع دوباره را نشان می‌دهد. اعلان طلاییِ باز شدن سرزمین، تا بسته شدن جشن حفظ می‌شود.

فونت وزیرمتن از Google Fonts بارگذاری می‌شود و در نبود شبکه، فونت پیش‌فرض مرورگر جایگزین است.

## بررسی

```sh
npm test
npm run build
npm run test:browser
```

آزمون‌های مرورگر از Chrome نصب‌شده روی سیستم استفاده می‌کنند؛ مرورگر بدون رابط گرافیکی نیز به‌کمک SwiftShader سه‌بعدی را اجرا می‌کند. آزمون‌ها ادغام، ذخیرهٔ کمک‌ها، بازگشت، انتخاب سه‌بعدی و جابه‌جایی، جارو، پنج تم با همهٔ سطوح سازه، پایان بازی و اندازه‌های موبایل را پوشش می‌دهند. هر چهار جهت مورب هم با ماوس و هم با لمس واقعی، آستانهٔ درگ، انتخاب با ضربه، و حفظ ذخیره‌های قدیمی بررسی می‌شوند. صدای امبینت با `OfflineAudioContext` رندر و شدت، ورود و محو شدن آن اندازه‌گیری می‌شود. ثبت نام و خطاهای آن، قفل سازه‌ها، تعداد کانتکست‌های پیش‌نمایش، انتخاب تم، دو جدول رتبه‌بندی، انصراف رایگان از جابه‌جایی، رد درخواست کمک، جشن سطح نهایی و ثبت پایدار پایان بازی نیز آزمون مرورگر دارند. آزمون‌های سرویس، یکتایی نام‌ها، مصرف هم‌زمان کمک، مرز روز تهران و ثبت تکراری نتیجه را مستقل بررسی می‌کنند. تصاویر بررسی در `test-results/` تولید می‌شوند.
